# Experiment 2: Maintenance, the language wall, and a smaller model

**Date:** 2026-07-14 · Follow-up to
[`2026-07-14-authoring.md`](2026-07-14-authoring.md), probing the three
caveats it left open: (a) what happens when an intent *exceeds* the
language, (b) whether AI maintenance of an existing bundle works (the
failure mode that killed model-driven engineering), and (c) whether
guide-only authoring survives on a smaller model.

Same protocol as before: agents restricted to
[`docs/upl-for-agents.md`](../docs/upl-for-agents.md) as their only
language reference, real `uplc check`/`uplc test` loop, max 8 repair
rounds, verbatim error logging.

## Results

| Probe | Model | First check | First test | Repairs | Outcome |
|---|---|---|---|---|---|
| Blog needing relations (beyond the language) | Sonnet | fail | pass | 1 | Graceful degradation + precise wall report |
| Maintenance: extend inventory (restock + low-stock view) | Sonnet | pass | pass | 0 | All old contracts kept; 3→6 test cases |
| Cold-start authoring: expense log with `where` query | Haiku | pass | pass | 0 | Fully correct, used day-old features |

### (a) The wall: agents fail loudly and design well

The blog intent ("comments on a specific post") was chosen because the
language couldn't express it. The agent hit the wall exactly where
predicted, and its behavior is the important finding:

- It did **not** hallucinate syntax into the final artifact or silently
  degrade. Its one repair round was at the wall itself (it tried a
  second `id`-typed field as a foreign key; the compiler rejected it).
- It ran **disposable probe files** to map the boundary — testing
  whether `(ref Entity)` and query `(input ...)` existed, and recording
  the exact rejections.
- It shipped the best legal approximation (post id as a plain text
  field, unscoped comment list) with every compromise documented.
- It proposed concrete syntax for what it needed: a `(ref Entity)`
  field type with enforced existence, parameterized queries, and a way
  for UI to pass a row's field into a nested query/action.

**The compiler's whole-bundle name resolution is what made this safe:**
every fabricated construct died at `check`, so nothing invented could
reach the runtime.

### (b) Maintenance: the bundle stayed authoritative

The maintenance agent extended the inventory bundle (new restock action
with a 1–1000 input contract, a where-filtered low-stock list) with
zero repairs, preserved every existing contract and test, and reported
the edit was *easier* than green-field because the existing bundle
supplied the idioms to imitate. It also surfaced a UX gap: no way to
act on a row with a user-supplied value (it resorted to a type-the-id
form).

### (c) Haiku: cold-start holds two model tiers down

Haiku matched Sonnet: first-try pass, zero repairs, correct `where`
query, and — decisively — correct use of `(row N (as name))` ordering
assertions, a feature that had existed for about an hour and appears
nowhere except the guide. That rules out training-data leakage as an
explanation for these results: the agents really are authoring from
the spec in context.

## What we changed in response (same day)

The wall report and the maintenance gap defined the next language
version, implemented immediately:

1. **`(ref Entity)` fields** — referential integrity enforced at write
   time (400 on dangling ids), `(on-delete restrict)` by default,
   `(on-delete cascade)` opt-in (restrict checks run before cascades;
   cascades are one level deep by construction).
2. **Parameterized queries** — `(input (post_id id))` + `where` over
   fields ∪ inputs; served as `GET /api/query?param=value`.
3. **Row-scoped nested UI** — list items may contain nested lists
   (`(list (query comments_for_post (post_id id)) ...)`) and nested
   forms with hidden binds (`(bind post_id id)`) — which also closes
   the maintenance agent's "act on a row with a user-supplied value"
   gap.
4. **Parameterized test checks** —
   `(check (comments_for_post (post_id (. p id))) ...)`.

[`examples/blog.upl`](../examples/blog.upl) — written in almost
exactly the syntax the agent proposed — now passes 4/4 cases,
including FK rejection, cascade delete, and scoped-comment assertions,
and the nested per-post comment form works in a real browser. The
maintained inventory bundle (6/6 cases) replaced the original example.

## Read-out

- The failure mode at the language boundary is the *good* one: loud,
  precise, and generative. An agent that cannot express a requirement
  produces a design proposal instead of a lie, because the compiler
  refuses everything else. This suggests a development loop where the
  language grows by shipping intents slightly beyond it.
- Maintenance — where model-driven engineering historically died —
  shows the opposite dynamic here: the bundle's explicitness made the
  edit easier, not harder. One data point, but the right direction.
- Remaining known gaps, in rough priority: aggregates in queries
  (counts/sums), auth/multi-user, schema migrations for deployed apps,
  update-style forms prefilled from a row, and the edit-lift tool
  (fold a hand-patch to generated code back into a bundle delta).
